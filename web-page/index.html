Is It Just Me, or the Whole Area?

A community map for reporting power, water and internet outages and blocked roads in Sri Lanka. Anyone can drop a pin to report a problem, see whether neighbours have the same problem, add a "me too" or mark it resolved. No login and no exact home location stored.

View on GitHub

Problem

When the power, water or internet goes out or a road is blocked, people are left guessing and calling each other to find out what is happening.

  • Nobody knows whether the outage is just their house or the whole area.
  • Nobody knows when it will come back.
  • There is no simple shared place to see outages nearby.

Solution

OutageMap turns single reports into a shared live picture. Nearby reports of the same type are grouped, neighbours confirm them with one tap and a history map shows which areas lose service most often.

  1. 1Tap the map, choose the type and add an optional short note.
  2. 2See reports of the same type within 500 m grouped into one circle.
  3. 3Add "me too" to a report, or mark it resolved when service is back.
  4. 4Review the busiest areas and fixed problems over 7, 30 or 90 days.

Features

A small set of features that follows an outage from the first report to the moment it is fixed.

  • Report in seconds

    Tap the map, choose Power Water Internet or Blocked road and add an optional note of up to 140 characters.

  • Grouped reports

    Reports of the same type within 500 m become one circle that shows the count.

  • Me too and Resolved

    One "me too" per device per report. A resolved report leaves the live map at once.

  • Busiest areas

    1 km squares with the most reports in 7, 30 or 90 days, with the typical outage length.

  • Fixed problems

    A list of resolved reports with when each was reported, fixed and how long it took.

  • Private and safe

    No login, no IP stored, pins rounded to about 100 m and a rate limit per IP.

Architecture

A three-tier web application. A React single-page app calls a Go REST API over HTTPS. The API runs spatial SQL on PostgreSQL with PostGIS. Map images load directly from OpenStreetMap.

Data Flow

Three flows show how data moves through the system: reporting an outage, seeing grouped outages and the history map.

Report an outage

  1. The user taps the map and a form opens at that point.
  2. POST /api/reports is sent with the type, location and an anonymous device ID.
  3. The API checks the rate limit and validates the input.
  4. The location is rounded to about 100 m and saved in PostGIS.

See grouped outages

  1. The map sends its visible area every 30 seconds.
  2. GET /api/clusters?bbox=… reads active reports in that area.
  3. PostGIS groups them per type within 500 m with ST_ClusterDBSCAN.
  4. The map draws one coloured circle per group with its count.

History

  1. The user picks 7, 30 or 90 days and an optional type.
  2. GET /api/history?days=30 is sent.
  3. PostGIS groups reports into 1 km squares with ST_SnapToGrid.
  4. The page shows the busiest squares with counts and typical outage length.
